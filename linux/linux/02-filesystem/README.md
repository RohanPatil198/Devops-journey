# Linux Filesystem

## Overview

The Linux filesystem is the hierarchical structure used by Linux to organize files, directories, system configuration, applications, logs, devices, processes, and other system information.

Unlike Windows, where storage is commonly represented using drive letters such as `C:` or `D:`, Linux presents the system through a **single directory tree** beginning at the root directory `/`.

Everything in the Linux system is accessible somewhere under `/`.

A simplified filesystem hierarchy looks like this:

```text
/
├── boot
├── dev
├── etc
├── home
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sys
├── tmp
├── usr
└── var
```

Understanding this hierarchy is important for Linux administration and DevOps because applications, configurations, logs, services, storage, and system information are located in different parts of the filesystem.

---

# 1. Linux Filesystem Hierarchy

The Linux filesystem starts at:

```text
/
```

This is called the **root directory**.

It is not the same as:

```text
/root
```

`/` is the root of the entire filesystem hierarchy, while `/root` is the home directory of the root user.

For example:

```text
/
├── etc
├── home
├── var
└── root
```

All of these directories are located below `/`.

You can view the root directory using:

```bash
ls /
```

For detailed information:

```bash
ls -la /
```

# 2. Important Linux Directories

Understanding the purpose of the major directories is more important than simply memorizing their names.

| Directory | Purpose                                                  |
| --------- | -------------------------------------------------------- |
| `/`       | Root of the filesystem hierarchy                         |
| `/boot`   | Files required for system booting                        |
| `/dev`    | Device files                                             |
| `/etc`    | System and application configuration                     |
| `/home`   | Home directories of normal users                         |
| `/media`  | Common location for removable media                      |
| `/mnt`    | Common temporary mount location                          |
| `/opt`    | Optional or third-party software                         |
| `/proc`   | Virtual filesystem containing process/kernel information |
| `/root`   | Home directory of the root user                          |
| `/run`    | Runtime data created since boot                          |
| `/sys`    | Virtual filesystem containing kernel/device information  |
| `/tmp`    | Temporary files                                          |
| `/usr`    | User-space applications, libraries and supporting files  |
| `/var`    | Variable data such as logs, caches and application data  |

The most important directories for everyday DevOps work are generally:

```text
/etc
/var
/home
/opt
/tmp
/var/log
/proc
/sys
/dev
```

---

# 3. `/etc` — Configuration

The `/etc` directory contains system-wide configuration files.

Examples include:

```text
/etc/hostname
/etc/hosts
/etc/passwd
/etc/group
/etc/fstab
/etc/ssh/
/etc/systemd/
```

Applications and services commonly store their configuration under `/etc`.

For example, SSH configuration is commonly located under:

```text
/etc/ssh/
```

You can inspect it with:

```bash
ls -la /etc/ssh/
```

### Why `/etc` matters in DevOps

When troubleshooting an application or service, you often need to find its configuration.

For example:

```text
Application
    ↓
Configuration
    ↓
/etc/
    ↓
Service behavior
```

A service may fail because of:

* Incorrect configuration
* Invalid path
* Wrong permissions
* Incorrect port
* Invalid credentials
* Configuration syntax errors

Therefore, knowing `/etc` is essential for system administration.

---

# 4. `/var` — Variable Data

`/var` contains data that changes while the system is operating.

Examples include:

```text
/var/log
/var/cache
/var/lib
/var/tmp
```

The contents of `/var` can grow over time.

For example:

```bash
sudo du -sh /var/*
```

can help identify which directories are consuming space.

### Important `/var` directories

#### `/var/log`

Contains system and application logs.

```bash
ls -lah /var/log
```

Logs are important for:

* Troubleshooting
* Security investigation
* Monitoring
* Application debugging
* Incident investigation

#### `/var/lib`

Contains persistent application and service data.

Different services may maintain their data here.

#### `/var/cache`

Contains cached data generated by applications and package managers.

---

# 5. `/home` — User Home Directories

Normal users generally have their home directories under:

```text
/home
```

For example:

```text
/home/rohan
```

The `~` symbol normally represents the current user's home directory.

Therefore:

```bash
cd ~
```

is equivalent to going to your home directory.

You can check the location with:

```bash
pwd
```

### Why `/home` matters

Your personal:

* Scripts
* Git repositories
* Configuration files
* Documents
* Development files

can be stored here.

For example:

```text
/home/rohan/devops-journey
```

could contain your DevOps learning repository.

---

# 6. `/root` — Root User's Home

`/root` is the home directory of the **root user**.

It is different from:

```text
/
```

For example:

```text
/       → Entire filesystem
/root   → Root user's home directory
```

Normal users generally cannot access everything under `/root`.

---

# 7. `/tmp` — Temporary Files

`/tmp` is used for temporary files created by applications and users.

Example:

```bash
touch /tmp/test.txt
```

The exact lifecycle of files in `/tmp` depends on the Linux distribution and its configuration. Temporary data should not generally be treated as permanent storage.

### DevOps relevance

`/tmp` is frequently used during:

* Installation
* Temporary processing
* Scripts
* Build operations
* Testing

However, important application data should not be stored there unless the application specifically requires it.

---

# 8. `/opt` — Optional Software

`/opt` is commonly used for optional or third-party application software.

For example:

```text
/opt/application/
```

A manually installed application might place its files there.

The exact installation location depends on the software and its installation method.

---

# 9. `/usr` — User-Space Software

`/usr` contains a large part of the operating system's user-space software and supporting files.

Important locations include:

```text
/usr/bin
/usr/sbin
/usr/lib
/usr/share
```

### `/usr/bin`

Contains many user commands and executable programs.

For example:

```bash
ls /usr/bin
```

### `/usr/sbin`

Contains many system administration commands.

### `/usr/lib`

Contains libraries used by applications and system programs.

### `/usr/share`

Contains architecture-independent shared data such as documentation and other resources.

---

# 10. `/boot` — Boot Files

`/boot` contains files required during the system boot process.

You can inspect it with:

```bash
ls -lah /boot
```

It may contain:

* Linux kernel images
* Initial RAM filesystem images
* Bootloader-related files

A problem with boot-related files can prevent the system from starting correctly.

---

# 11. `/dev` — Device Files

Linux represents devices through files under:

```text
/dev
```

Examples include:

```text
/dev/sda
/dev/null
/dev/random
```

Storage devices can appear as block devices, while special devices such as `/dev/null` provide kernel-supported interfaces.

For example:

```bash
ls -la /dev
```

### `/dev/null`

`/dev/null` is a special device that discards data written to it.

For example:

```bash
echo "test" > /dev/null
```

The text is discarded.

This is commonly used in scripts when output is not required.

Example:

```bash
command 2>/dev/null
```

This discards standard error from the command.

---

# 12. `/proc` — Process and Kernel Information

`/proc` is a **virtual filesystem**.

It is not simply a normal directory containing files stored permanently on disk.

The Linux kernel exposes information through `/proc`.

For example:

```bash
cat /proc/cpuinfo
```

displays CPU-related information.

```bash
cat /proc/meminfo
```

displays memory-related information.

You can also see process-related directories:

```text
/proc/1
/proc/2
/proc/...
```

Many numeric directories correspond to process IDs (PIDs).

### Why `/proc` matters

It provides useful information for:

* System monitoring
* Troubleshooting
* Process investigation
* Performance analysis
* System administration

---

# 13. `/sys` — Kernel and Hardware Information

`/sys` is another virtual filesystem.

It provides information and interfaces related to:

* Hardware devices
* Device drivers
* Kernel subsystems
* System devices

For example:

```bash
ls /sys
```

and:

```bash
ls /sys/class
```

Unlike `/proc`, which focuses heavily on processes and kernel information, `/sys` is strongly associated with the device model and kernel subsystems.

---

# 14. `/run` — Runtime Data

`/run` contains temporary runtime information created after the system boots.

It can contain information such as:

* Process IDs
* Unix sockets
* Service runtime data
* Other system runtime state

The contents of `/run` are not intended to be permanent application storage.

---

# 15. `/mnt` — Mount Point

`/mnt` is traditionally used as a temporary mount location.

For example, if you have another filesystem:

```text
/dev/sdb1
```

you could mount it at:

```text
/mnt/data
```

Conceptually:

```text
/dev/sdb1
    ↓
Filesystem
    ↓
/mnt/data
```

After mounting, the filesystem's contents become accessible through `/mnt/data`.

---

# 16. `/media` — Removable Media

`/media` is commonly used for mounting removable storage such as USB drives.

Desktop Linux systems often manage removable devices automatically.

The exact behavior depends on the distribution and desktop environment.

---

# 17. Filesystem vs Directory

These terms are related but not identical.

### Directory

A directory is a location used to organize files.

Example:

```text
/etc
/var/log
/home/rohan
```

### Filesystem

A filesystem is the data structure and rules used to organize and manage data on storage.

Examples include:

```text
ext4
XFS
Btrfs
NTFS
```

You can identify filesystem types with:

```bash
df -Th
```

or:

```bash
lsblk -f
```

---

# 18. Disk, Partition, Filesystem and Mount Point

These four concepts should not be confused.

A simplified storage structure is:

```text
Physical/Virtual Disk
        ↓
     Partition
        ↓
    Filesystem
        ↓
    Mount Point
        ↓
    Files/Directories
```

For example:

```text
/dev/sda
    ↓
/dev/sda2
    ↓
ext4
    ↓
/
    ↓
/etc
/var
/home
```

The exact layout depends on how the operating system was installed.

---

# 19. Block Devices

Storage devices are commonly represented as block devices.

Examples:

```text
/dev/sda
/dev/sdb
/dev/nvme0n1
```

Partitions may appear as:

```text
/dev/sda1
/dev/sda2
```

or for NVMe devices:

```text
/dev/nvme0n1p1
/dev/nvme0n1p2
```

You can inspect storage devices using:

```bash
lsblk
```

For filesystem information:

```bash
lsblk -f
```

---

# 20. Mounting

Linux makes filesystems accessible by **mounting** them into the directory tree.

For example:

```bash
sudo mount /dev/sdb1 /mnt/data
```

This means:

```text
/dev/sdb1
    ↓
mounted at
    ↓
/mnt/data
```

After mounting, users can access the filesystem through:

```bash
cd /mnt/data
```

The mount point must normally exist before mounting.

```bash
sudo mkdir -p /mnt/data
```

---

# 21. Unmounting

When a filesystem is no longer needed, it can be unmounted.

```bash
sudo umount /mnt/data
```

Unmounting removes the filesystem from the active directory hierarchy.

If the filesystem is currently being used, Linux may report:

```text
target is busy
```

In that situation, you need to identify the processes using it before safely unmounting it.

Useful commands include:

```bash
lsof
```

and:

```bash
fuser
```

---

# 22. `/etc/fstab`

The file:

```text
/etc/fstab
```

contains information about filesystems that Linux can mount automatically.

It can define:

* Device/UUID
* Mount point
* Filesystem type
* Mount options
* Dump settings
* Filesystem check settings

A common approach is to use UUIDs rather than relying only on device names.

You can inspect it with:

```bash
cat /etc/fstab
```

Be careful when modifying `/etc/fstab`. An incorrect configuration can cause boot or mount problems.

---

# 23. UUID

A filesystem can have a UUID, or **Universally Unique Identifier**.

You can view UUIDs using:

```bash
sudo blkid
```

or:

```bash
lsblk -f
```

Example:

```text
/dev/sda2
UUID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
TYPE="ext4"
```

UUIDs are useful because device names can vary depending on hardware and system detection, while a filesystem UUID identifies that filesystem.

---

# 24. Inodes

An inode is a filesystem data structure containing metadata about a file.

It can contain information such as:

* File type
* Permissions
* Owner
* Group
* File size
* Timestamps
* Links
* Information used to locate the file's data

You can view inode numbers with:

```bash
ls -li
```

Example:

```text
123456 -rw-r--r-- 1 rohan rohan 100 file.txt
```

Here:

```text
123456
```

is the inode number.

The filename itself is associated with the inode through the filesystem's directory structure.

---

# 25. File Timestamps

Linux maintains several important timestamps.

### Access time — `atime`

Indicates when file contents were accessed.

### Modification time — `mtime`

Indicates when the file's contents were modified.

### Change time — `ctime`

Indicates when the file's metadata changed.

You can inspect them using:

```bash
stat filename
```

For example:

```bash
stat /etc/hostname
```

Understanding timestamps is useful when investigating:

* Configuration changes
* Application files
* Logs
* Security incidents
* Troubleshooting

---

# 26. Disk Usage

Two commands are particularly important:

```text
df
du
```

They answer different questions.

### `df`

Reports filesystem-level disk-space usage.

```bash
df -h
```

Question answered:

> How much space is available on this filesystem?

### `du`

Reports the space consumed by files/directories.

```bash
du -sh /var/log
```

Question answered:

> Which directory or files are consuming the space?

A common troubleshooting flow is:

```text
df
 ↓
Identify full filesystem
 ↓
du
 ↓
Identify large directory
 ↓
find
 ↓
Identify large/problematic files
```

---

# 27. Finding Files

Linux provides `find` for searching the filesystem.

Basic syntax:

```bash
find [PATH] [EXPRESSION]
```

Example:

```bash
find /var/log -type f
```

Find files by name:

```bash
find /etc -name "*.conf"
```

Find directories:

```bash
find /var -type d
```

Find large files:

```bash
find /var -type f -size +100M
```

This is particularly useful for troubleshooting disk usage.

---

# 28. Symbolic and Relative Paths

Linux supports both absolute and relative paths.

### Absolute path

Starts from `/`.

Example:

```text
/etc/ssh/sshd_config
```

This identifies a specific location regardless of your current directory.

### Relative path

Starts from your current directory.

For example:

```bash
cd ~/filesystem-lab
cat test.txt
```

Here `test.txt` is interpreted relative to the current directory.

Special path components:

```text
.    → Current directory
..   → Parent directory
~    → Current user's home directory
/    → Root directory
```

# 29. Hidden Files

Linux files beginning with `.` are normally treated as hidden by directory listing tools.

Examples:

```text
.bashrc
.profile
.git
```

To display them:

```bash
ls -a
```

To display detailed information:

```bash
ls -la
```

Hidden does not mean secure or encrypted. It mainly affects normal directory listing behavior.

---

# 30. Filesystem Permissions

Filesystem objects have permissions controlling access.

A typical listing might look like:

```text
-rw-r--r-- 1 rohan rohan 100 file.txt
```

The permission section:

```text
-rw-r--r--
```

contains:

```text
-       → File type
rw-     → Owner permissions
r--     → Group permissions
r--     → Other permissions
```

Permissions will be studied in greater depth in the **Users, Groups and File Permissions** topics.

---

# 31. Virtual Filesystems

Some Linux filesystem locations don't represent traditional files stored on a disk.

Important examples include:

```text
/proc
/sys
/dev
```

These interfaces allow user-space programs to interact with information and functionality provided by the kernel.

For example:

```bash
cat /proc/meminfo
```

can provide current memory information.

This is one of the reasons Linux administration often involves inspecting files that are not ordinary persistent files.

# 32. Filesystem Troubleshooting

A common production problem is:

```text
No space left on device
```

A systematic investigation can begin with:

```bash
df -h
```

Determine which filesystem is full.

Then:

```bash
df -Th
```

Determine the filesystem type.

Next investigate directories:

```bash
sudo du -sh /* 2>/dev/null | sort -h
```

If `/var` is large:

```bash
sudo du -sh /var/* 2>/dev/null | sort -h
```

If logs are responsible:

```bash
sudo du -sh /var/log/*
```

Then locate large files:

```bash
sudo find /var/log -type f -size +50M -ls
```

This provides a logical investigation process rather than randomly deleting files.

# 34. Common Mistakes

### Mistake 1 — Confusing `/` and `/root`

```text
/       → Entire filesystem hierarchy
/root   → Root user's home directory
```

### Mistake 2 — Confusing `df` and `du`

```text
df → Filesystem capacity
du → File/directory usage
```

### Mistake 3 — Assuming `/dev/sda` is always the main disk

Device names depend on the environment.

Always check:

```bash
lsblk
```

### Mistake 4 — Treating `/proc` as normal persistent storage

`/proc` is a virtual filesystem exposed by the kernel.

### Mistake 5 — Deleting files when disk usage is high

First investigate:

```bash
df
du
find
```

Understand what is consuming space before removing anything.

### Mistake 6 — Modifying `/etc/fstab` without understanding it

An incorrect filesystem configuration can cause mount or boot problems.
